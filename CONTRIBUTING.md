# Contributing

## Commit and PR title format

Every PR is squash-merged, so the **PR title** becomes the one commit
message that lands on `main` — that's the only thing enforced, not
every intermediate commit on your branch. A CI check
(`amannn/action-semantic-pull-request`) rejects PR titles that don't
match [Conventional Commits](https://www.conventionalcommits.org/):

```
<type>(<scope>): <subject>
```

### Types

| Type | Meaning | Version bump |
|---|---|---|
| `feat` | a new capability | minor |
| `fix` | a bug fix | patch |
| `perf` | a measurable performance improvement | patch |
| `refactor` | restructures code, no behavior change | none |
| `docs` | documentation only | none |
| `style` | formatting, no logic change | none |
| `test` | adding or fixing tests | none |
| `build` | build system, packaging, dependency wiring | none |
| `ci` | CI/CD configuration itself | none |
| `chore` | maintenance that doesn't fit elsewhere | none |
| `revert` | reverts an earlier commit | depends |

Breaking change: `type(scope)!: subject`, or a `BREAKING CHANGE:`
footer in the PR body — either forces a major bump.

### Scopes (optional, but use one when it fits)

`sync-engine` · `transport` · `persistence` · `ui` · `git-sync` ·
`packaging` · `deps` (used by Dependabot's own commits)

### The `User-Facing:` footer

The PR title is deliberately terse. For any `feat` or `fix` that
actually changes behavior someone would notice, add a `User-Facing:`
line in the **PR body** — this is what actually shows up in the
generated changelog and release notes, instead of the raw commit
subject:

```
fix(transport): handle WireGuard handshake timeout

The pairing handshake had no timeout, so a peer that dropped
mid-handshake would hang the pairing flow indefinitely.

User-Facing: Pairing with an unreachable peer now fails after 30
seconds instead of hanging forever.
```

Keep it to one line — it's a git trailer, not a paragraph. Not every
PR needs one: a `docs:` or `chore:` change usually doesn't have
user-facing behavior to describe.

### Why the PR body, not commit messages on your branch

Squash merge uses the **PR title** as the commit subject and the
**PR body** as the commit body — so `BREAKING CHANGE:` and
`User-Facing:` footers belong in the PR description, not buried in
one of several commits inside the branch. Commit messages within a PR
can be as messy as you need them to be; only the PR title and
description are enforced and preserved.

## What happens after merge

[`release-plz`](https://release-plz.dev/) watches every push to
`main`. It maintains an always-up-to-date Release PR showing the
accumulated changelog (generated by
[`git-cliff`](https://git-cliff.org/), config in `cliff.toml`) and the
next `Cargo.toml` version, computed from the commit types above plus
`cargo-semver-checks` catching any undeclared breaking change.
Merging that Release PR is the actual release: it tags the commit and
creates a GitHub Release with the changelog attached. Publishing to
crates.io is currently disabled (`release-plz.toml`) since this is an
internal component, not yet meant for external `cargo add`.
